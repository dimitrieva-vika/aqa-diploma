## 1. Перечень автоматизируемых сценариев

### 1.1. Валидные тестовые данные

Для позитивных сценариев используются следующие данные:

| Поле | Значение | Пример |
|------|----------|--------|
| Номер карты (APPROVED) | 16 цифр, формат xxxx xxxx xxxx xxxx | 4444 4444 4444 4441 |
| Номер карты (DECLINED) | 16 цифр, формат xxxx xxxx xxxx xxxx | 4444 4444 4444 4442 |
| Месяц | 01-12 | 08 |
| Год | Текущий год или позже | 26 |
| Владелец | Имя на латинице | Ivan Petrov |
| CVC/CVV | 3 цифры | 123 |

### 1.2. Позитивные сценарии

#### Сценарий 1: Успешная покупка тура (Debit Card)
**Действия:**
1. Нажать кнопку "Купить"
2. Заполнить поле "Номер карты": 4444 4444 4444 4441
3. Заполнить поле "Месяц": 08
4. Заполнить поле "Год": 26
5. Заполнить поле "Владелец": Ivan Petrov
6. Заполнить поле "CVC/CVV": 123
7. Нажать кнопку "Продолжить"

**Ожидаемый результат:**
- Появляется уведомление: "Успешно! Операция одобрена Банком."
- В БД (таблица `payment_entity`) появляется запись со статусом `APPROVED`
- В таблице `order_entity` появляется запись с `payment_id`

## 3. Перечень и описание возможных рисков

| № | Риск | Описание | Вероятность | Влияние | Способы минимизации |
|---|------|----------|-------------|---------|---------------------|
| 1 | **Изменение селекторов** | Верстка страницы приложения может измениться, что "сломает" UI-тесты. | Средняя | Высокое | Использовать стабильные `data-test-id` атрибуты. Избегать XPath. Регулярно поддерживать тесты. |
| 2 | **Проблемы с окружением** | Сложности при одновременном поднятии MySQL, PostgreSQL и эмулятора в Docker. | Низкая | Высокое | Использовать `docker-compose.yml` с настроенными портами. Проверить наличие свободных портов. |
| 3 | **Нестабильность SUT** | Приложение содержит баги, влияющие на стабильность тестов. | Высокая | Среднее | Правильно разделять ошибки теста и баги приложения. Баги фиксировать в Issues. |
| 4 | **Баг №1: PostgreSQL** | При запуске с PostgreSQL таблицы не создаются. | Высокая | Высокое | Использовать MySQL для выполнения тестов. Баг зафиксирован в Issues. |
| 5 | **Баг №2: DECLINED** | При отказе банка фронт показывает успешное сообщение. | Высокая | Высокое | Автотесты будут падать на негативных сценариях. Баг зафиксирован в Issues. |
| 6 | **Баг №3: CVC** | Ошибка валидации CVC отображается у поля "Владелец". | Высокая | Среднее | Учесть баг при написании проверок. Баг зафиксирован в Issues. |
| 7 | **Долгое выполнение тестов** | Большое количество UI-тестов может замедлить прогон. | Низкая | Среднее | Оптимизировать тесты, использовать параллельный запуск. |
| 8 | **Отсутствие тестового стенда** | Тесты выполняются на локальной машине. | Низкая | Среднее | Использовать Docker для изолированного окружения. |

## 7. Рекомендации

1. **Приоритет автоматизации:**
    - Начать с позитивных сценариев (Сценарии 1-2)
    - Затем реализовать проверки БД (Сценарии 15-16)
    - После этого - негативные сценарии и валидацию формы

2. **Работа с багами:**
    - Баг №2 (DECLINED) критичен - автотесты будут падать
    - Временно можно проверять, что БД сохраняет `DECLINED`, а сообщение игнорировать
    - Все баги должны быть зафиксированы в Issues

3. **Тестовые данные:**
    - Для позитивных сценариев использовать карту 4444 4444 4444 4441
    - Для негативных - 4444 4444 4444 4442
    - Остальные поля генерировать через Faker

4. **Отчетность:**
    - Интегрировать Allure для наглядных отчетов
    - Прикладывать скриншоты к баг-репортам
